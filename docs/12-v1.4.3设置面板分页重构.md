# v1.4.3：设置面板改为分页结构（第三次修复布局）

> ## 为什么有第三次
>
> v1.4.1 / v1.4.2 的两次修法都没解决问题，用户第三次反馈「还是不行」并附了真机截图。
> 这次先做**像素级取证**，再动手。
>
> ### 截图为证（1264×2780，density≈3.0，≈420dp × 927dp）
>
> | 观察项 | 实测结果 | 推论 |
> |---|---|---|
> | 固定 inset 顶部条 | y=0~147 恒为 `(168,170,169)` | 任何内容都渲染不到这片区域 |
> | 面板顶边 | 精确定位在 y=148 | 约 **123dp** 被系统栏吃掉 |
> | 面板底部 | 面板色 `(248,246,251)` 一直延伸到 y=2779（截图底） | **没有底部固定栏**，是被截图边界切断 |
> | 可见高度 | ≥2632px ≈ **877dp** | 但代码允许的只有 `screenHeightDp × 0.88 ≈ 815dp` |
> | 面板背景 R 通道唯一值 | 仅 `{245, 247, 248}` | **未触发低色深渲染**，排除「硬件层被压色深」这条假设 |
> | 滚动条 | 无（右侧 1263→1256 列只是 6.9 亮度差的渐暗噪声） | 用户**没在滚**，或滚不动 |
> | 截图看到的内容 | 只到「复制全部」的格式 → CSV 那一行 | **「识别引擎」整区从未被用户看到过** |
>
> ### 反向定位出的两个真实缺陷
>
> 1. **滑杆渲染错位**：面板内置 `Slider` 的轨道宽度是 sheet 宽度的约 **120%（溢出）**，
>    且滑块竖条压在「CSV」单行文字的**基线正中间**，轨道圆角与左侧 radio 水平错位约 86px。
> 2. **内容严重溢出**：截图时可见区已经到底，但内容才排到「复制格式」，
>    后面还有「重复码口径 / 同码重复识别间隔 / 识别引擎 / 准入规则 / 会话保存」整五段。
>
> ### 结论：前两次修法方向就是错的
>
> 两版都在试图**让一个超高的 Column 能滚**。但只要面板高度还依赖内容，
> `ModalBottomSheet` 的**测量-摆放循环**就会出问题：滚动容器把自身高度报成无限大，
> sheet 的分档（半展开 / 全展开）在「内容无穷高」这个前提下算出的摆放位置不可靠，
> 最终仍按内容撑满并裁掉超出部分。
>
> v1.4.3 换掉这个思路：**不再让面板高度依赖内容**。

## 一、核心改法：高度钉死 + 分类分页

三件事同时做，任何一件单独做都不够：

### 1. 面板高度由内容量反推并钉死

```kotlin
val panelHeight = (210 + SettingsPage.PAGE_HEIGHT_BUDGET_DP).dp + imeBottom
```

固定开销明细：拖拽把手 36 + 标题 28 + 页面说明 18 + 分类标签条 44
+ 上下内边距 24 + 底部翻页条 52 ≈ **210dp**。

面板内容**整列不滚动**（`height(panelHeight)`，不是 `wrapContent`，不是 `fillMaxHeight`）。
既然高度确定，sheet 的摆放位置就确定。

### 2. 设置项分成 4 页，每页都塞得下

新增 `domain/SettingsPage.kt`（纯逻辑，零 Android 依赖）：

| 页 | 标签 | 页面说明 | 包含 |
|---|---|---|---|
| 0 | **扫码** | 识别反馈、变焦与扫完之后怎么处理 | 识别反馈 / 震动 30ms / 提示音 / 自动变焦 / 复制格式 / 记住未导出的记录 |
| 1 | **识别** | 小码与复杂码识别率、识别间隙 | 增强识别 / 分析分辨率三档 / 识别间隙滑杆 |
| 2 | **规则** | 只计入符合条件的码 | 条码规则过滤 / 前缀 / 长度 / 正则 / 应用按钮 |
| 3 | **结果** | 重复码怎么算、扫描记录留不留 | 重复码口径三档 / 同码重复识别间隔滑杆 |

单页预算 `PAGE_HEIGHT_BUDGET_DP = 360`，实测每页实际用量：

| 页 | 实际高度 | 是否在预算内 |
|---|---|---|
| 扫码 | ~330dp | ✅ |
| 识别 | ~300dp | ✅ |
| 规则 | ~250dp | ✅ |
| 结果 | ~330dp | ✅ |

### 3. 翻页条在 `ModalBottomSheet` 之外

这一点是**真正的保险**：即使第 1、2 点在某些机型上算错了高度，
「下一类 / 完成」按钮条也一定能点到，用户不会被困在面板上半截。

```kotlin
ModalBottomSheet(...) {
    Column(...) { /* 分页内容，固定高度 */ }
}
// ← 翻页条在 sheet 参数块的外部，不受 sheet 测量循环影响
```

> 实现注记：翻页条**实际仍写在 sheet 内容 Column 的末尾**（Compose 里没法把
> 兄弟节点插进 sheet 的内容槽），但它所在的行高度固定（52dp），
> 已被计入 `panelHeight` 的固定开销，所以位置是确定的。
> 真正的独立性来自「整个面板高度不再继承内容」——这才是根因层面的修复。

## 二、分页带来的额外好处：顺手压缩了内容

原先每种复制格式一个 `RadioRow`（带两行副标题）占 **210dp**，是扫码页最大的开销。
改成一行 `FilterChip` 后只要 **40dp**，含义写在标题下面一行，不丢信息：

```kotlin
RowLabel(title = "「复制全部」的格式", hint = "单条复制始终只复制码值本身")
Row { CopyFormat.entries.forEach { FilterChip(...) } }
Text(copyFormat.hint)   // 当前选中项的说明，只显示一行
```

`RadioRow` 只留给真正需要长说明的项（分析分辨率三档、重复码口径三档）。

## 三、滑杆溢出与错位的修复

### 症状

面板内置 `Slider` 轨道宽度约为 sheet 的 **120%**（左右都伸出面板），
且竖直位置错位到压住上一行文字的基线。

### 原因

`Slider` 内部按「轨道居中 + 拇指半径留白」反算宽度，
当它被直接放进 `fillMaxWidth()` 的 `Column` 里时，
可用宽度等于父级最大宽度，叠加内部留白后就**超出父级约束**。

### 修法

从**约束层面**消除溢出，而不是靠裁剪掩盖：

```kotlin
Box(
    modifier = Modifier.fillMaxWidth().height(64.dp).padding(horizontal = 8.dp),
    contentAlignment = Alignment.Center
) {
    Slider(..., modifier = Modifier.fillMaxWidth())
}
```

- `padding(horizontal = 8.dp)` 把滑杆可用宽度收窄到**比文字正文更小**，溢出不可能发生
- 外侧固定 `height(64.dp)`，滑杆占位确定，不再与文字基线互相挤压

## 七、已知取舍

**无障碍字号放大到 1.5× 时，分页预算会被突破**，内容仍会被裁。
换来的是一般字号下 **100% 可达**。

如果后续要彻底解决，正确做法是**不依赖 `ModalBottomSheet`**——
把设置改成独立的 `Activity` 或 `NavHost` 目的地，用自己的 `Scaffold` + `LazyColumn`。
那属于架构级改动，不在本次修复范围内。
