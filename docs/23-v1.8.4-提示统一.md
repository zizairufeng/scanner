# v1.8.4 — 扫描页提示统一：8 处浮层收敛成 3 个落点

## 一句话

扫描画面上原来有 **8 处各自的浮层**（6 种颜色、5 个落点、4 档时长），现在只剩
**3 个固定落点**、**3 种语义色**、**2 档时长**；同一时刻每个落点最多一条。

## 改之前的实际情况

| 落点 | 内容 | 原颜色 | 原时长 |
|---|---|---|---|
| 预览顶中 12dp | 识别成功值 | 绿 `31C48D` | 260ms |
| 预览左上 48dp | 性能角标 | 橙 `7A3E00` | 常驻 |
| 预览底中 14dp | 疑似有码 | 琥珀 `B26A00` | 1.2s |
| 预览底中 46dp | 太近失焦 | 红橙 `A02C00` | 3.5s |
| 预览中下 100dp | 「方码压在中心」 | 黑 40% | **常驻** |
| 预览右下 | 缩放倍率 | 黑 60% | 常驻 |
| 屏幕顶 72dp | 重复码轻提示 | 反转色 | 2.5s |
| 屏幕顶 72dp | Snackbar | 反转色 | 4s |

四个具体毛病：

1. **纵坐标撞车**：「识别成功值」在预览卡片内 12dp，屏幕级「重复码提示」在 72dp
   ≈ 卡片内 16dp。两者只差 4dp —— 扫到一个重复码时，两条不同的提示几乎叠在同一个位置。
2. **底部叠两条**：「疑似有码」和「太近失焦」是两条独立状态，可以同时出现，
   一上一下堆在画面底部。
3. **一条常驻**：「方码压在中心 · 四边留白」永远显示，恰好压在取景框下沿——
   那是画面上最该看清的一块。
4. **六种颜色没有语义**：绿色和琥珀色分别表示什么，全凭当时写代码的人随手挑。

## 改之后的规范

新增 `ui/components/ScanHint.kt`，把规范写死在代码里：

```
落点 1（屏幕顶 72dp）  ：刚才发生了什么 —— 单条
                          Snackbar(可操作) > 重复码 > 识别成功
落点 2（预览底 14dp）  ：你现在该怎么做 —— 单条
                          太近失焦 > 疑似有码 > 位置引导
落点 3（四角角标）     ：状态，不是提示
                          左上：性能  右下：倍率
```

**语义色只有三种**：`SUCCESS` 绿 `#1FA96F` / `ACTION` 琥珀 `#B26A00` / `NEUTRAL` 黑 60%。

**时长只有两档**：`INFO_MS = 2.5s`（看一眼就够）/ `ACTION_MS = 3.5s`（要你抬手调整）。

## 具体改了哪几处

1. **识别成功值从预览卡片挪进屏幕顶部槽**，与重复码提示共用同一个 `HintCard`
   （深色卡 + 语义色圆点 + 两行字），只有圆点是绿的。标题从裸码值变成
   「已计入 · 第 12 条」，用户不用再自己数。
2. **顶部槽做优先级**：Snackbar 在时不渲染另外两条（它带「撤销」按钮，必须能点到）；
   重复码提示在时不渲染识别回执（它说得更具体）。
   **只是让位，不取消**——重复码提示仍由自己的计时器收起。
3. **底部两条合并成一个 `guide` 状态**，按 `Guide` 枚举声明顺序排优先级，
   高优先级直接顶替。
4. **「方码压在中心」从常驻改成进场 8 秒**：它是新手常识，第一次看到就够；
   之后只在「太近失焦」时由那条更具体的提示接管。
5. **性能角标回到左上 12dp**：原先躲到 48dp 是为了避让识别成功值，那条已经走了。
6. **文案统一用「·」分隔**：不再混用冒号、逗号、括号。
7. **取景框闪光色与 `HintSuccess` 同一个绿**：同一个「扫到了」全页面只允许一个绿。

## 为什么规则要写成测试

新增 `ScanHintSpecTest`，断言：时长只有两档且信息档更短、`HintTone` 恰好三种、
顶部槽位落在顶栏之下、底部指引不会被右下角倍率压住。

这类腐化靠 review 挡不住——它每次只多加"一条"。所以让规则变成断言：
以后谁想加第四种语义色或第三档时长，先让测试红，等于强制在评审里讨论一次。
