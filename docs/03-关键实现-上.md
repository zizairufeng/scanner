# 三、关键实现（上）：权限、相机绑定、图像分析

> 完整代码已在工程里，本节只摘决定行为正确性的那几行并说明理由。
> 文件路径都是真实可打开的。

## 3.1 权限声明

`app/src/main/AndroidManifest.xml`

```xml
<!-- CAMERA：唯一需要运行时申请的权限 -->
<uses-permission android:name="android.permission.CAMERA" />
<!-- VIBRATE：normal 级权限，安装即授予、不弹窗；系统强制要求，否则震动静默失效 -->
<uses-permission android:name="android.permission.VIBRATE" />

<uses-feature android:name="android.hardware.camera.any" android:required="true" />
<uses-feature android:name="android.hardware.camera.flash" android:required="false" />
```

- **没有** `READ_MEDIA_IMAGES` / `READ_EXTERNAL_STORAGE`：相册用 Photo Picker，系统按次授权。
- `camera.any required="true"`：无摄像头设备不给装，避免装完就是一块废砖。
- `camera.flash required="false"`：无闪光灯机型仍可安装，代码里做能力探测降级。

## 3.2 依赖清单

`app/build.gradle.kts`

```kotlin
val cameraxVersion = "1.4.1"
implementation("androidx.camera:camera-core:$cameraxVersion")
implementation("androidx.camera:camera-camera2:$cameraxVersion")
implementation("androidx.camera:camera-lifecycle:$cameraxVersion")   // 与 Lifecycle 自动绑定
implementation("androidx.camera:camera-view:$cameraxVersion")        // PreviewView
implementation("com.google.mlkit:barcode-scanning:17.3.0")           // 捆绑模型，端侧离线
```

依赖取舍说明：

- **ML Kit 选 `barcode-scanning` 而非 `barcode-scanning-*` 变体**：这是「模型打进 APK」的捆绑版，首次启动即可用，不依赖 Google Play 服务去下载模型（有些仓库手机没有 GMS，用 unbundled 版会一直卡在下载）。
- 不引入 ZXing：ZXing 已停更，其对 Data Matrix 的识别率明显低于 ML Kit，且没有端侧模型优化。
- **不引入 `kotlinx-coroutines-play-services`**：只为 `await` 多一个依赖不值当，用 `util/TaskAwait.kt` 的 12 行 `suspendCancellableCoroutine` 自己桥接。
- **不引入 `material-icons-extended`**：会引入上万矢量图标（APK 体积），核心图标集已够用，复制/删除用文字与 `Icons.Filled.Delete` 表达。

## 3.3 权限申请与降级

`app/src/main/java/com/example/scanstock/ui/ScanScreen.kt`（节选）

```kotlin
val permissionLauncher = rememberLauncherForActivityResult(
    contract = ActivityResultContracts.RequestPermission()
) { isGranted ->
    requestedOnce = true
    granted = isGranted
    if (!isGranted) {
        scope.launch { snackbarHostState.showSnackbar("未获得相机权限，你仍可用相册导入图片识别") }
    }
}

// 从系统设置返回时重新校验：用户可能刚在设置里打开了权限
DisposableEffect(lifecycleOwner, context) {
    val observer = LifecycleEventObserver { _, event ->
        if (event == Lifecycle.Event.ON_RESUME) granted = context.hasCameraPermission()
    }
    lifecycleOwner.lifecycle.addObserver(observer)
    onDispose { lifecycleOwner.lifecycle.removeObserver(observer) }
}

// 「永久拒绝」判定：拒绝过 + 系统不再展示弹窗
val permanentlyDenied = !granted && requestedOnce &&
    (context.findActivity()
        ?.shouldShowRequestPermissionRationale(Manifest.permission.CAMERA) ?: false).not()
```

三个容易踩的坑，这里都处理了：

1. **`ON_RESUME` 重新校验**。否则用户去设置里开了权限、切回来，界面还是「需要权限」的死人脸。
2. **永久拒绝分支**。`shouldShowRequestPermissionRationale` 返回 false 意味着再调 `launch` 也**不会弹窗**，必须把按钮换成「去系统设置」，否则用户点了没反应会以为 App 坏了。
3. **降级路径不为空**。需求要求「禁止白屏」——即使一行相机代码都没跑起来，顶栏的「相册」按钮**始终可点**，用户靠图片照样能完成盘点。这是把降级做成真的可用，而不是一句提示。

## 3.4 相机绑定（Preview + ImageAnalysis）

`app/src/main/java/com/example/scanstock/ui/components/CameraPreviewCard.kt`（节选）

```kotlin
DisposableEffect(lifecycleOwner) {
    val analyzerExecutor = Executors.newSingleThreadExecutor()   // 单线程：天然串行，不会并发解析
    val scanner = BarcodeFormats.createScanner()
    val analyzer = BarcodeAnalyzer(
        scanner = scanner,
        onResult = { codes -> currentOnDetected(codes) },   // lambda 经 rememberUpdatedState 包装
        onError = { e -> currentOnError(e) }
    )

    val future = ProcessCameraProvider.getInstance(context)
    val bindRunnable = Runnable {
        if (disposed) return@Runnable                 // 防止 DisposableEffect 已销毁后才回调
        val cameraProvider = future.get()

        val resolutionSelector = ResolutionSelector.Builder()
            .setAspectRatioStrategy(AspectRatioStrategy.RATIO_16_9_FALLBACK_AUTO_STRATEGY)
            .setResolutionStrategy(
                ResolutionStrategy(Size(1280, 720), ResolutionStrategy.FALLBACK_RULE_CLOSEST_LOWER_THEN_HIGHER)
            ).build()

        val preview = Preview.Builder().build()
            .also { it.surfaceProvider = previewView.surfaceProvider }

        val imageAnalysis = ImageAnalysis.Builder()
            .setResolutionSelector(resolutionSelector)
            .setBackpressureStrategy(ImageAnalysis.STRATEGY_KEEP_ONLY_LATEST)  // ★ 只留最新帧
            .build()
            .also { it.setAnalyzer(analyzerExecutor, analyzer) }

        cameraProvider.unbindAll()                     // 旋转重建时先解绑，避免 UseCase 重复绑定
        val bound = cameraProvider.bindToLifecycle(
            lifecycleOwner, CameraSelector.DEFAULT_BACK_CAMERA, preview, imageAnalysis
        )
        maxZoom = bound.cameraInfo.zoomState.value?.maxZoomRatio ?: 1f
        onCameraReady(maxZoom, bound.cameraInfo.hasFlashUnit())
    }
    future.addListener(bindRunnable, ContextCompat.getMainExecutor(context))

    onDispose {
        disposed = true
        runCatching { provider?.unbindAll() }
        analyzerExecutor.shutdown()     // 必须关线程池，否则每次旋转都泄漏一个线程
        runCatching { scanner.close() }
    }
}
```

四个关键点：

1. **`STRATEGY_KEEP_ONLY_LATEST` + 单线程 Executor**：这是「连续扫描不暂停」的发动机。CameraX 只保留最新一帧交给分析器，中间帧直接丢。**预览不受影响**，因为 Preview 是另一个独立 UseCase。
2. **`disposed` 标志**：`ProcessCameraProvider.getInstance` 是异步的，用户可能在这期间就退出页面了。没有这个标志，回调里访问已销毁的 `PreviewView` 会崩。
3. **`unbindAll` 在 bind 之前**：旋转屏幕会重建 Composable，不先解绑会抛 `IllegalArgumentException: Use case already bound`。
4. **`analyzerExecutor.shutdown`**：最容易漏的一行。每次旋转都泄漏一个单线程池，扫 20 分钟能耗尽线程。

闪光灯与缩放跟随状态，用 `LaunchedEffect` 而不是在按钮里直接调 `cameraControl`——这样「状态是唯一真相」，用户从设置或别处改状态，硬件行为也会跟着变：

```kotlin
LaunchedEffect(torchOn, camera) { camera?.cameraControl?.enableTorch(torchOn) }
LaunchedEffect(zoomRatio, camera, maxZoom) {
    camera?.cameraControl?.setZoomRatio(zoomRatio.coerceIn(1f, maxZoom))
}
```

双击缩放靠 `pointerInput` 挂在预览外层 `Box` 上（`PreviewView` 本身不消费触摸）：

```kotlin
.pointerInput(zoomRatio, maxZoom) { detectTapGestures(onDoubleTap = { onDoubleTapZoom() }) }
```

`onDoubleTapZoom` 只是改状态 `zoomRatio = if (当前 > 1.05f) 1f else 2f`，由上面的 `LaunchedEffect` 落到硬件。

## 3.5 图像分析器（背压闸门 + 自动摆正）

`app/src/main/java/com/example/scanstock/camera/BarcodeAnalyzer.kt`（核心 10 行）

```kotlin
@OptIn(ExperimentalGetImage::class)
override fun analyze(imageProxy: ImageProxy) {
    val mediaImage = imageProxy.image
    if (mediaImage == null) { imageProxy.close(); return }   // 切镜头瞬间偶发空图

    // rotationDegrees 由 CameraX 按设备姿态算好，传进去 ML Kit 自动摆正
    val inputImage = InputImage.fromMediaImage(mediaImage, imageProxy.imageInfo.rotationDegrees)

    scanner.process(inputImage)
        .addOnSuccessListener { barcodes -> onResult(barcodes.map { toDetectedCode(it) }) }
        .addOnFailureListener { onError(it) }          // 单帧失败不致命，只上报
        .addOnCompleteListener { imageProxy.close() }  // ★ 放在 complete 里 = 背压闸门
}
```

**为什么 `close` 必须放在 `addOnCompleteListener` 里**：`ImageProxy` 持有相机缓冲区，不释放 CameraX 就永远不送下一帧。同时这也形成了一个天然的「分析未完成 → 不投喂新帧」闸门，配合 `KEEP_ONLY_LATEST` 后：

- 不会出现多个 `process` 并发跑同一份缓冲（那会直接崩）；
- 不会积压帧导致「扫完实时画面滞后 3 秒」；
- 预览照常 30fps 刷新。

「疑似条码但没解出来」的处理：`BarcodeScannerOptions.enableAllPotentialBarcodes` 会让 ML Kit 额外返回「检测到有条码但解码失败」的目标，它们的 `rawValue == null`。代码把它们标成 `DetectedCode(potentialOnly = true)`：

```kotlin
val raw = barcode.rawValue
DetectedCode(
    formatId = barcode.format,
    formatName = BarcodeFormats.nameOf(barcode.format),
    value = raw ?: "",
    potentialOnly = raw.isNullOrEmpty()   // ← 只用于提示，绝不进列表
)
```

UI 侧收到底层这个信号后弹一条黄色提示「疑似有码，再靠近 / 稳住一下」，1.2 秒后自动淡出。这是暗光/模糊场景下**唯一**能区分「没对准」和「手机坏了」的反馈——比一句笼统的「请对准条码」有用得多。
