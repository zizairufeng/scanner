# 五、真机验收清单

> 逐条勾选。每条都给了「怎么测」和「什么算通过」。建议在**仓库/货架实景**跑一遍，不要只在桌面上摆一张打印的条码。

## A. 首次启动与权限

- [ ] **A1 拒绝权限不白屏**：全新安装 → 首次弹窗点「拒绝」→ 应看到权限说明页（含「授予相机权限」+「去系统设置」两个按钮），**不是白屏，也没崩溃**。
- [ ] **A2 永久拒绝引导正确**：再点一次「授予相机权限」→ 点「拒绝」→ 此时按钮应变成单个「去系统设置」（说明 `shouldShowRequestPermissionRationale` 分支生效）。
- [ ] **A3 从设置返回自动恢复**：在 A2 状态下点「去系统设置」→ 手动打开相机权限 → 返回 App → **无需重启**，预览应自动出现。
- [ ] **A4 无相机权限也能干活**：在 A1 的拒绝状态下点顶栏「相册」→ 选一张有条码的图 → 应能识别并追加到列表。

## B. 码制覆盖（7 种逐个验证）

准备实物或屏幕显示：EAN-13（超市商品）、EAN-8（小包装）、UPC-A（进口商品）、Code-128（物流面单）、Code-39（工业标签）、QR Code、Data Matrix（电子元件/医疗器械标签）。

- [ ] **B1** 逐个扫描，**每种都在列表里显示正确的码制名**（不是全显示成 EAN-13）。
- [ ] **B2 UPC-A 专项**：UPC-A 码值应为 12 位且码制显示 `UPC-A`；EAN-13 码值 13 位显示 `EAN-13`。若你的样品上 UPC-A 被回报成 EAN-13（加前导 0），属 ML Kit 的正常行为，记录实际表现即可（已在假设第 5 条说明）。
- [ ] **B3 误识率**：把摄像头对准货架上**没有条码的区域**（纯文字价签、包装图案）扫 30 秒，列表**不应增加任何记录**。

## C. 连续扫描与去重（核心）

- [ ] **C1 不刷屏**：把手机**固定**对准同一个码，保持 10 秒不动。列表应**只增加 1 条**。
- [ ] **C2 移开再扫可再计**：移开让画面里完全没有该码，等约 2 秒再对准 → 应**新增 1 条**（说明去重窗口可释放）。用这个方式连扫 5 次同一个码，应得到干净连续的 5 条记录。
- [ ] **C3 预览不卡**：连续快速扫 20 个不同商品，预览画面应始终流畅，**不出现「画面里的码已经拿开了、列表才跳出来」的延迟**。
- [ ] **C4 不连震**：C1 的 10 秒里，只应有 **1 次**震动与 **1 声**提示音，而不是嗡嗡持续。
- [ ] **C5 窗口可调生效**：设置里把去重时间窗拖到 3000ms → 重复 C2，应需要离开画面约 3 秒才能重新计入。
- [ ] **C6 一秒多条**：把 10 个不同商品的码依次快速掠过（每个停留约 0.5 秒），应**全部 10 条**都被记录，无漏记。
- [ ] **C7 快速补扫同款（仿真已预警）**：扫一件商品 → 移开约 0.3 秒 → 立刻扫第二件同款。
      在默认 1500ms 窗口下，**第 2 件会被判为重复而不计入**（这是需求规定的 1.5 秒窗口的必然结果，不是 bug）。
      把设置里的滑杆拉到 **300ms** 再重复一次，**应能正常计入第 2 条**，同时保持 C1（固定对准 10 秒只记 1 条）仍成立。
- [ ] **C8 帧率边界**：若你在弱光下观察到偶发重复（同一码记了两次），把去重窗口上调 200~500ms 即可。
      原因见 `docs/06-验证报告.md` §2.2 —— 低帧率下「有效遮挡时长」有 ±1 帧间隔的不确定度。
- [ ] **C9 去重开关生效**（v1.1 修订）：点预览下方的「去重 开」→ 变为「去重 关」（普通高亮配色）。关闭后同一个码**离开画面满时间窗**即可再次录入（允许重复计数）；开启后列表里已有的码**无论隔多久**都不会重复计入。两种状态下持续对准一个码都**不会**一秒记几十条（时间窗防刷屏始终生效）。
      此时固定对准同一个码 3 秒 → 列表应**逐帧增长**（20fps 下约 60 条）——这就是关闭去重的预期行为，不是 Bug。
      再点一下切回「去重 开」→ 列表立即停止增长（固定对准仍只记 1 条，即 C1 依然成立）。
      **验完请务必切回「去重 开」**，常规盘点必须保持开启。
- [ ] **C10 开关不影响同帧去重**（本轮新增）：关闭去重后，对着一张**印有 5 个相同二维码**的图片用「相册」识别 → 应只增加 **1 条**（同帧去重不被开关放开）。

## D. 列表操作

- [ ] **D1** 每行显示：序号、码制、内容、时间（精确到毫秒，如 `14:32:07.418`），且**序号与时间都在递增**。
- [ ] **D2 单条删除**：删第 5 条 → 第 5 条消失，第 6 条**序号仍是 6**（不重排，见假设第 3 条）。
- [ ] **D3 自动滚底**：扫到第 30 条时列表应贴着底部；手动上滑翻看历史，此期间新扫的码**不应把你强行拽回底部**。
- [ ] **D4 清空**：点「清空」→ 列表清空 → **立刻重扫刚才那个码，应立刻新增 1 条**（说明 `dedupe.reset()` 生效，不需要等 1.5 秒）。

## E. 复制

- [ ] **E1 单条复制**：点任意一行 → Snackbar 显示「已复制该条码值」（**不并列格式名**，因为单条复制与格式设置无关）→ 粘到记事本，内容应为**纯码值**（不带序号、不带 Tab）。
- [ ] **E2 默认格式是纯文本**：全新安装、没动过设置时，底部按钮上应直接写着 **「复制全部 (N) · 纯文本」** → 点一下 → 粘到微信输入框，应为**每行一个纯码值**，没有序号、没有 Tab。
- [ ] **E3 序号+Tab 格式**：设置里切到「序号+Tab」→ 底部按钮文案应同步变成「复制全部 (N) · 序号+Tab」→ 复制全部 → 粘到 **Excel** → 应自动分成两列（序号 / 内容），共 N 行。
- [ ] **E4 CSV 格式**：设置改成「CSV」→ 复制全部 → 粘到记事本，首行应为 `序号,码制,内容,时间`；用含**逗号或引号**内容的 QR 码（例如 `{"a":1,"b":"x"}`）验证，字段应被双引号正确包裹、内部引号翻倍。
- [ ] **E5 空列表**：清空后点「复制全部」→ 提示「列表为空，没有可复制的内容」，**不写入空剪贴板**。
- [ ] **E6 大量数据**：扫 200 条以上再复制全部 → 不应卡顿或 OOM；粘到 Excel 应完整 200 行。

## F. 反馈设置

- [ ] **F1** 关掉「识别反馈」总开关 → 扫描**不震不响**，但列表照常追加。
- [ ] **F2** 只关「提示音」→ 仍震动、无声音。
- [ ] **F3** 只关「震动 30ms」→ 仍有提示音、不震动。
- [ ] **F4** 手机开启静音/勿扰模式 → 提示音仍应可闻（用了 `STREAM_MUSIC` 而非通知流）。

## G. 辅助功能

- [ ] **G1 闪光灯**：点「闪光灯 关」→ 变「闪光灯 开」且**补光灯真的亮了**；再点关闭。
- [ ] **G2 无闪光灯机型**（可选，用前置摄像头改默认或模拟器）→ 点击应提示「当前镜头没有闪光灯」，按钮**不应卡在「开」的假状态**。
- [ ] **G3 双击缩放**：双击预览 → 画面放大到 2x 且右下角出现 `2.0x` 角标 → 再双击回到 1x、角标消失。
- [ ] **G4 相册识别**：选一张**横拍且有条码**的图 → 应正确识别（验证 `InputImage.fromFilePath` 的 EXIF 摆正生效），并提示「图片解析完成，共发现 N 个条码」。
- [ ] **G5 相册无码**：选一张风景照 → 提示「图片里没有识别到条码…」，**不崩溃**。

## H. 生命周期与稳定性

- [ ] **H1 旋转不丢数据**：扫 10 条 → 旋转屏幕 → 列表**仍是 10 条**，序号连续，预览正常（无黑屏、无「Use case already bound」崩溃）。
- [ ] **H2 反复旋转不泄漏**：连续旋转 10 次 → 相机预览每次都正常；用 Android Studio Profiler 看线程数**不应持续增长**（验证 `analyzerExecutor.shutdown()` 生效）。
- [ ] **H3 后台不占相机**：切到桌面再打开系统相机 App → 系统相机应能正常打开（说明本 App 后台已释放相机）。
- [ ] **H4 返回前台可用**：从后台切回 → 预览自动恢复，且**不会重放「已复制」Snackbar**。
- [ ] **H5 相机被占用**：先用其他 App 占住相机（如微信视频通话中），再打开本 App → 应给出可读提示而**不闪退**。
- [ ] **H6 边界条码**：尝试扫描以下内容，均应正常显示且复制无碍：
  - [ ] 含中文的 QR 码（如「设备编号：A-001」）
  - [ ] 超长内容（1000 字符以上的 QR 码，列表行应省略显示，但复制内容完整）
  - [ ] 含换行符的 QR 码（CSV 导出时应被引号包裹）

## I. 离线与性能

- [ ] **I1 完全离线可用**：飞行模式 + 关 Wi-Fi → 冷启动 App → 扫描功能**完全正常**（验证捆绑模型打进 APK，不依赖网络）。
- [ ] **I2 冷启动**：从点击图标到预览出现，中端机应 ≤ 2 秒。
- [ ] **I3 连续续航**：连续扫描 30 分钟，机身**不应明显发烫**（验证 1280×720 分析分辨率与 KEEP_ONLY_LATEST 的功耗控制）。
- [ ] **I4 确认网络权限确已从 APK 移除**（本轮新增）：进入系统「设置 → 应用 → 盘点扫描 → 权限」，**不应出现任何「网络 / 联网」权限项**，只应有「相机」与振动类。若看到网络权限，说明 `AndroidManifest.xml` 里的 `tools:node="remove"` 没生效。
- [ ] **I5 移除网络权限后功能无损**（本轮新增，**本轮最需要你验证的一条**）：飞行模式 → 冷启动 App → 连续扫描 10 个商品 → 应全部正常识别、无崩溃、无卡顿。ML Kit 的统计上报在没有网络权限时会静默跳过，不应影响识别。若出现异常，删掉 manifest 里那两行 `tools:node="remove"` 即可回滚。

## J. 已知取舍（验收时不算 Bug）

- [ ] **J1** App 被系统杀死后重新打开，**列表为空**——需求明确不落库，属预期行为。
- [ ] **J2** 序号删除后不重排——设计如此，见假设第 3 条。
- [ ] **J3** 同一帧里多个完全相同的码只记 1 条——设计如此，且**关闭去重后依然如此**（同帧去重不随开关放开，见假设第 9 条）。
- [ ] **J4** 粘贴 CSV 到 Excel 若出现中文乱码，是 Excel 默认按本地编码解析所致，导入时选 UTF-8 即可（未写 BOM 是刻意选择，见假设第 4 条）。
- [ ] **J5** 默认 1500ms 窗口下，移开不足 1.5 秒的快速补扫会被判为重复（见 C7）——这是需求规定的窗口，改成 300ms 可解决。**不要**改用「关掉去重」来绕过它：关闭去重是允许重复录入同一码（满窗口后计入），计件请用 300ms 窗口。
