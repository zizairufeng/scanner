# v1.4 新增：小码识别率提升 + 可调「识别间隙」

> ## 布局问题修复史（v1.4.1 → v1.4.2 → v1.4.3 → v1.4.4）
>
> v1.4 首次安装后反馈「设置里没有新增项，而且排版是乱的」。根因经历了四轮才彻底解决：
>
> ① v1.4.1 — 面板整体被裁切
> 设置面板加了一整区之后总高度约 **1970dp**，而手机可见高度只有 **600~700dp**。
> `ModalBottomSheet` 的内容 `Column` **没有滚动能力**，超出部分被**直接裁掉**（不是滚动到底）。
> → 加 `verticalScroll(rememberScrollState)` + `heightIn(max = 屏高 × 0.88)`。
>
> ② v1.4.2 — 行内文字被固定高度切掉（这是「排版乱」的直接来源）
> `SwitchRow` / `RadioRow` 都写死了 `.height(56.dp)`。副标题在窄屏上会折成 2~3 行，
> 固定高度装不下就被静默裁掉，文字显示成被切一半的样子。
> → 改用 `.heightIn(min = 56.dp)`，让行高跟着文字实际行数长；开关与文字之间补 12dp 间距。
>
> ③ v1.4.3 — 前两次方向就是错的：滚动救不了 ModalBottomSheet
> 用户第三次反馈「还是不行」并附截图。像素级取证后确认：截图里可见区已经到底，
> 但内容才排到「复制格式」，后面还有五整段（含新增的「识别引擎」）从未被看到过。
>
> 根因：只要面板高度还依赖内容，`ModalBottomSheet` 的**测量-摆放循环**就会出问题——
> 滚动容器把自身高度报成无限大，sheet 的分档在「内容无穷高」前提下算出的摆放位置不可靠，
> 最终仍按内容撑满并裁掉超出部分。加滚动本身就在加固这个坏前提。
>
> → 换思路：面板高度由内容量反推并钉死，设置项分成 4 页，翻页靠底部固定按钮条。
> 详见 [`12-v1.4.3设置面板分页重构.md`](./12-v1.4.3设置面板分页重构.md)。
>
> ④ v1.4.4 — 钉死了，但装不下：内容盖在翻页条上
> 用户第四次反馈「还是存在元素重叠」。这次**先做了定量取证**而不是直接改代码：
> 按 Material3 默认排版逐项复算每页高度，发现 v1.4.3 那个拍脑袋定的 360dp 预算四页有三页超出
> （扫码 513 / 识别 498 / 结果 389，最多溢出 153dp）。
> 而内容区是 `Box(weight(1f))`——**既不裁剪也不滚动**，多出来的部分只能直接画在翻页条上。
>
> → 双保险：预算 360 → 520dp（依据 sheet 上限 834 − 固定开销 210 = 624）+ 内容区在钉死高度内可滚动。
> 后一条是真正的保险——预算再算错也只是变成滑动，不会退化成重叠。
> 详见 [`13-v1.4.4元素重叠修复.md`](./13-v1.4.4元素重叠修复.md)。
>
> 四处都不是打包问题 —— `aapt dump badging` 确认包内版本号一直是正确的。
> Compose 的固定尺寸容器 + 文本溢出是**静默失败**：不报错、不警告，只是把内容切掉。
>
> ⑤ v1.5.0 — 补上「准确率」这条腿
> 布局这条线到此收束。识别侧又做了两项（**不换库**，改进管线）：
> **校验位自校验**（挡掉解错一位的误识）+ **ROI 二次精读**（裁候选区放大重扫，对症小码）。
> 设置面板相应变化：新增「小码精读」开关，「规则」页改名「准确」并合入「校验位检查」，
> 内容预算 520 → **545dp**（识别页复算升到 491dp）。
> 详见 [`15-v1.5识别准确率与ROI精读.md`](./15-v1.5识别准确率与ROI精读.md)。
>
> 当前版本 **1.5.0（versionCode 10）**。

## 一句话

v1.3 的两个遗憾一次补上：小二维码 / 复杂二维码识别率靠分辨率档位 + 增强识别拉起来；
**「识别间隙」**拆成两个可调参数。默认值与 v1.3 **完全一致**，不调就不变。

## 一、为什么之前小码难识别

根因不在 ML Kit，而在**分析帧的分辨率**。

CameraX 的 `ImageAnalysis` 默认取一个"够用"的分辨率。v1.3 把它硬编码成 1280×720：

```kotlin
// v1.3（旧）
.setResolutionStrategy(
    ResolutionStrategy(Size(1280, 720), FALLBACK_RULE_CLOSEST_LOWER_THEN_HIGHER)
)
```

720p 对**大条码**完全够用，单帧耗时低、连续扫描帧率高，是个很稳的默认值。
但小二维码的问题是——它在 1280×720 的分析帧里可能只占 20×20 像素，
模块（黑白格子）宽度不到 2 像素。ML Kit 再强也无法从信息已经丢失的像素里还原内容。

**关键认知**：`cameraControl.setZoomRatio` 放大的是**预览**，分析帧尺寸不变，
小码在分析帧里依然只占那么点像素。所以"光靠自动变焦救不了远距小码"——
必须同时提高分析分辨率。这正是 v1.4 把两者绑在一起调的原因。

---

## 二、分析分辨率档位

新增 `ScanTuning.AnalysisProfile` 三档：

| 档位 | 分辨率 | 像素倍数 | 适用场景 | 单帧耗时趋势 |
|---|---|---|---|---|
| `BALANCED` | 1280×720 | 1.0×（基准） | 大码、近距离、长时间盘点 | 最低 |
| `SHARP` | 1920×1080 | 2.25× | 小码、中远距离 | 中 |
| `ULTRA` | 2560×1440 | 4.0× | 极细密 / 高版本复杂码 | 最高 |

默认 `BALANCED` —— 与 v1.3 行为完全一致，零回归。

设备不支持某档位时，`FALLBACK_RULE_CLOSEST_LOWER_THEN_HIGHER` 会自动降档，
不会因为选了 1440p 而在老设备上绑相机失败。

## 三、增强识别开关

一个开关，做两件事：

1. **抬档位**：当前档位低于 1080p 时自动抬到 1080p。
2. **抬变焦上限**：可用变焦上限抬到至少 `4.0×`（受硬件真实上限约束，不会凭空放大）。

规则在 `ScanTuning.profileWithBoost` 里，并有两条单测锁定语义：

- 不会把用户的主动选择降级：用户手动选了 1440p 后再开增强，仍保持 1440p。
- 关掉增强不回落档位：档位是用户的显式选择，开关只管"要不要额外加码"。

## 四、「识别间隙」拆成两个独立参数

原请求里的"识别码的间隙"有两种可能含义，v1.4 **两个都做了**，且互不干扰：

### 4.1 分析帧间隔（`frameIntervalMs`）—— 省电侧

"每隔多久才送一帧去识别引擎"。

- 范围 **0 ~ 500ms**，步长 50ms，**0 = 不节流**（每帧都送，= v1.3 行为）
- 实现：`BarcodeAnalyzer` 开头的闸门，未到间隔的帧**直接 `close` 丢弃**，
  连 `InputImage` 都不构造 —— 省掉的不只是 ML Kit 推理，还有对象分配
- 设置面板实时显示 `≈N 帧/秒` 供判断
- **不需要重建相机**：`frameIntervalMs` 是 `@Volatile` 字段，
  改完下一帧 `analyze` 就读到新值；同时重置节流时钟，避免"改完还要等一整个新间隔"的迟钝感

### 4.2 同码重复识别间隔（`DedupeTracker.windowMillis`）—— 去重侧

"同一个码离开画面多久后，才允许被重新计入"。

v1.3 的范围是 300~5000ms，v1.4 放宽到 **100~10000ms**：

| 边界 | v1.3 | v1.4 | 理由 |
|---|---|---|---|
| 下限 | 300ms | **100ms** | 抬手就能补扫同一件商品；100ms 仍高于相机帧间隔（~33ms），不会退化成每帧都记 |
| 上限 | 5000ms | **10000ms** | 对着整垛同款条码时，5 秒内仍可能被反复读到 |

新增 `DedupeTracker.normalizeWindow`，保证滑杆吸附到 100ms 整数倍且不越界。

## 五、关键实现：什么时候重建相机

这是本版本最容易出错的地方。

| 参数 | 是否需要重建相机 | 原因 |
|---|---|---|
| `frameIntervalMs` | 不需要 | 分析器字段是 `@Volatile`，直接改即可 |
| `dedupeWindowMs` | 不需要 | 纯去重逻辑，与相机无关 |
| `analysisProfile` | **需要** | CameraX 的 `ImageAnalysis` 分辨率**绑定后不可变** |
| `enhancedRecognition` | **需要** | 它会影响档位与变焦上限，两者都只在绑定时生效 |

因此 `DisposableEffect` 的 key 是：

```kotlin
DisposableEffect(lifecycleOwner, analysisProfile, enhancedRecognition)
```

而 `frameIntervalMs` 单独走一个 `LaunchedEffect(frameIntervalMs, analyzerHolder)`，
把新值推给当前活跃的分析器实例 —— 依赖里带上 `analyzerHolder` 是必要的：
相机重建后 holder 会换成新实例，必须重新推一次，否则新分析器还带着旧间隔。

**副作用提示**：切档位会短暂重建相机画面。这是 CameraX 的固有限制，
已在设置面板文案里向用户说明（"切换档位会短暂重建相机画面，属正常现象"）。

## 六、设置面板改动

> 注意：v1.4 初版这里是**没有滚动**的，加完新区后内容超出屏幕被裁切 —— 已由 v1.4.1 修复。

新增「识别引擎」分区，位于「去重时间窗」之后：

```
识别引擎
  [ ] 增强识别（远距 / 小码）
  分析分辨率
    ( ) 标准 720p  ·  1.0×
    (•) 高清 1080p  ·  2.25×
    ( ) 超高 1440p  ·  4.0×
  识别间隙：不节流（约 30 帧/秒）
    [============|=========]
```

同时把原来的 `DedupeSlider` 泛化成通用 `StepSlider`（min/max/step 参数化），
两个滑杆共用一套吸附逻辑，避免两份重复实现走偏。

「同码重复识别间隔」的标题也从"去重时间窗"改成更直白的说法，
并在副标题里给出 100ms / 1500ms / 5000ms+ 三档参考值。

## 九、怎么用

扫小二维码解不出时，按顺序试：

1. 打开「增强识别」—— 一步搞定档位 + 变焦上限
2. 还不行就把分辨率手动拉到「超高 1440p」
3. 手机很烫或掉电快 → 把「识别间隙」调到 100~200ms 降温

快速连扫同一件商品（正常逐个盘点）：

- 「识别间隙」保持**不节流**
- 「同码重复识别间隔」调到 **100ms**

对着整垛同款条码，怎么晃都重复：

- 「同码重复识别间隔」调到 5000ms 以上
- 或把「重复码口径」切成「严格去重」
