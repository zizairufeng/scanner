# v1.8 — 金属蚀刻码（DPM）阶梯补扫

> 触发场景：用户拿手机扫海光（Hygon）CPU 顶盖上那颗方形码，怎么对都对不上，
> App 一点反应都没有。本文记录从「为什么扫不出」到「怎么改」的全部实测过程。

## 一、先说这颗码是什么

- **码制**：Data Matrix（不是 QR，虽然肉眼看着像）
- **生成方式**：**DPM（Direct Part Marking，直接零件标识）** —— 激光在金属表面蚀刻出的凹坑阵列
- **尺寸**：约 2.5mm × 2.5mm，26×26 模块
- **内容**：`HG62935B0166_C86-4G 7493`（正好等于旁边三行蚀刻字符的拼接）

「DPM」这三个字是整件事的关键：它不是印刷码，**码和底色是同一个颜色的金属**，
靠蚀刻凹坑的阴影反差成像。对比度通常只有几十级灰度，而印刷码是 200+ 级。

## 二、为什么扫不出（三层原因，逐层实测）

### 原因 1：ML Kit 对这类码**连候选框都不会给**

ML Kit 的条形码模型是对着「印刷码」训练的。这类蚀刻码在它的检测阶段就不成立，
所以 `task.result` 是空列表——**连 `boundingBox` 都没有**。

这一条的后果比想象中严重：App 原有的「ROI 精读」链路是
「粗检出候选框 → 按框裁剪 → 放大再解」，**候选框为空就整条链路都不触发**。
它不是「试了没成功」，而是「压根没开始」。

### 原因 2：反色 —— 蚀刻码是「浅码深底」

用 ZXing 对同一张裁块做消融实验（192 种组合里只有 8 种命中）：

| 组合 | 结果 |
|------|------|
| 原极性 + Hybrid / Global | ✗ |
| 原极性 + `ALSO_INVERTED` 提示 | ✗ |
| **反色 + `GlobalHistogramBinarizer`** | **✓ 8 种命中全在这一类** |
| 反色 + `HybridBinarizer` | ✗ |
| 反色 + 对比度拉伸 | ⚠ 部分命中，放大后反而变差 |

结论：
1. `DecodeHintType.ALSO_INVERTED` 在这类码上一次都没命中过，**必须手动反色**；
2. **`GlobalHistogramBinarizer` 才是正解**，`HybridBinarizer` 反而解不出
   —— 蚀刻码明暗差只有几十级，Hybrid 按 8×8 块算局部阈值，块内方差不够就判成纯色；
3. **不要做对比度拉伸**：蚀刻边缘是软过渡，2%/98% 分位拉伸会把它压平。

### 原因 3：分析区域只能比码大 1.2~1.8 倍（最关键）

在真实原图（1599×2844）上，以码中心为轴，裁不同大小的方块，看能否解出：

| 裁块边长 ÷ 码边长 | 0.9× | 1.2× | 1.5× | 1.8× | 2.1× | 2.4× | 3.0× | 4.5× | 6.0× |
|---|---|---|---|---|---|---|---|---|---|
| 结果 | ✗ | ✓ | ✓ | ✓ | ✗ | ✗ | ✗ | ✗ | ✗ |

**超过 2 倍就彻底解不出。** 原因：码周围一旦混进大片同色背景，
全局直方图二值化的阈值被背景拉偏，整张图被二值化成一片纯色，定位图案随之消失。

这条直接判了原有实现「死刑」：v1.7 的中心区补扫是**固定裁 60%**，
对一颗只占画面 5% 的码来说，那等于把裁块做到码的 12 倍——远远越过窗口。

## 三、改法：尺寸阶梯

既然不知道码在画面里有多大，就**按比例扫一遍**：

```
占短边比例： 1.00  0.77  0.59  0.45  0.35  0.27  0.21  0.16  0.12
裁块边长(720p)：720   554   424   324   252   194   151   115    86
```

相邻两级相差 1.3 倍，而黄金窗口宽 1.5 倍（1.8 / 1.2），
**数学上保证任意尺寸的码至少有一级落在 1.2~1.8 倍之内**。
这条性质写成了单测（`RoiPlannerDpmLadderTest` 里逐个尺寸验 48px~600px）。

配套的三个工程细节：

1. **先反色、再补白边**。顺序反了（先补白再反色）白边会被反成黑框，
   包在码外面那圈黑框会干扰定位图案搜索——实测同一条码就这样从「能解」变成「解不出」。
   这个坑是在用 Java 复刻解码流程时撞上的，已写成单测钉死。
2. **只跑 DataMatrix 单码制**。阶梯要连扫九级，`DataMatrixReader` 比 `MultiFormatReader`
   少一层「逐个 Reader 试」的外壳，单级省几十毫秒，九级下来手感差别很明显。
3. **上次命中的级别提到最前**。扫一整箱 CPU 时，第一级就中，后面八级不用跑。

## 四、成本控制

| 项 | 值 | 理由 |
|---|---|---|
| 触发条件 | 全帧一个码都没解出来 | 正常扫码快路径完全不受影响 |
| 阶梯间隔 | 400ms | 九级比中心区补扫贵得多，必须更保守 |
| 单帧预算 | 180ms | 超了立刻停，下一帧接着扫；保证帧率不低于约 5fps |
| 引擎 | 只 ZXing，不含 ML Kit | ML Kit 在这类码上从无命中，多问一次纯属浪费 |
| 开关 | 挂在「双引擎补扫（ZXing）」下 | 同一条依赖，不单开开关（识别页已到面板高度上限） |

## 五、验收

- **214/214 单元测试通过**（新增 11 条：阶梯几何、黄金窗口覆盖性、
  `order` 重排、非法入参、反色 DPM 端到端、原极性兜底）
- 实测样本：`HG62935B0166_C86-4G 7493` 从「完全扫不出」变为「可解」
- **未真机实测**：现场手感、阶梯实际耗时、命中所需距离，仍需手机验证

## 六、现场怎么扫（重要）

这类码本质上是**机器视觉级**难题，做不到「随手一拍就出」。实操建议：

1. **把码放到画面正中央**，占画面短边的 1/3 到 1/2（别把整颗 CPU 都框进来）；
2. **退到 15cm 左右**再双击切 2× 变焦——手机最近对焦距离普遍 10~12cm，贴太近物理上就是糊的；
3. **轻点屏幕对焦**，稳住 0.3 秒别动；
4. 有导热硅脂糊在码上时，**先擦掉**——硅脂会把蚀刻凹坑填平，那不是算法能救的。

## 七、下一步可选项（未做）

- **OCR 兜底**：这颗码旁边那三行蚀刻字符（`C86-4G` / `2427SUH 7493` / `HG62935B0166`）
  拼起来正好等于码内容，而字符比模块大 3 倍、对比度也高得多。
  加 ML Kit 文字识别后，正常拍摄距离就能读出来，比解 DPM 码宽容得多。
  代价是 +4MB 模型、以及需要一套「拼字段」的规则（可靠但不够通用）。
