# v1.8.1 — 重复码提醒从「弹框」改成「顶部轻提示」

> 用户原话：**「重复提醒，弹窗小一点，提示一下就行，不影响继续扫描。」**
>
> v1.7 做重复码提醒时选的是模态 `AlertDialog`，理由是「要看清码值再决定下一步」。
> 实际连扫两天后发现方向错了：把连续盘点的节奏整块切断，比信息不够详细更痛。

## 一、v1.7 的弹框错在哪

| 弹框行为 | 连扫现场的真实后果 |
|---|---|
| 屏幕中央遮罩，占 1/3 屏 | 挡住取景框中心，下一个码对没对准看不出来 |
| 必须点「知道了」才立刻消失 | 一只手拿着货、一只手拿手机，没人有空点 |
| 6 秒自动消失 | 等于「每扫到一个重复码，停 6 秒」 |
| 正文四段（码值 / 码制 / 位置 / 结果说明） | 真正有用的信息其实只有 1.5 行 |

结论：这类「你已经扫过它了」的信息，**是提示级，不是决策级**。
用户不需要读完、不需要应答，只需要知道「刚才那下没白扫」。

## 二、改成什么样

```
┌──────────────────────────────────────────┐
│ ● 重复码 · 未计入          第 3 行 · 第 2 次 │
│   JR5UCCB25B007JG                         │
└──────────────────────────────────────────┘
```

| 维度 | v1.7 弹框 | v1.8.1 轻提示 |
|---|---|---|
| 形态 | 模态 AlertDialog | 顶部浮条（高约 54dp，通栏） |
| 时长 | 6 秒 | **2.5 秒** |
| 是否拦截触摸 | 拦截（有遮罩） | **完全不拦截**，点哪儿都能对焦 |
| 是否影响布局 | 叠在整屏之上 | 叠在内容之上，列表不会上下跳 |
| 关闭方式 | 点「知道了」/ 点外面 / 超时 | 只能等超时 |
| 信息量 | 4 段文字 | 2 行（标题 + 码值） |
| 连续出现 | 屏上有就不再覆盖 | **直接换成最新一条** |

### 文案压缩的取舍

- **保留**：算没算（`未计入` / `已累计 ×8` / `已重复`）、码值、列表第几行、第几次扫到。
- **砍掉**：码制名、首次扫描时间（`09:31:12.480`）、「把手机移开」这类操作建议。

理由很硬：2.5 秒读不完三行以上的字。砍掉的信息在结果列表里全都能查到，
而「第几行」就是让用户知道去哪儿查的那个把手。

计数聚合模式下把数量直接写进标题（`已累计 ×8`），因为副标题已经腾给码值和位置，
不让用户做「这行到底几件」的心算。

## 三、实现要点（改这个组件时别破坏这三条）

### 1. 不进布局 —— 用 Box 叠层，不用 Column 里的条件渲染

`ScanScreen` 的最外层是 `Box { Scaffold(...); DuplicateHintOverlay(...) }`。
如果把提示条塞进 `Column` 里，它的出现/消失会**把相机预览和列表推得上下跳**，
连扫时画面抖一下就可能对不准下一个码。

### 2. 不吃触摸 —— 整棵子树没有任何 `clickable` / `pointerInput`

Compose 的命中测试只认注册了 pointer input 的节点，所以一个"纯展示"的
`Surface` 上面的点击会**穿透**到下面的相机预览，点哪儿都能对焦。
代价是没法手动关掉它——所以时长必须短（2.5 秒），不能像弹框那样留 6 秒。

> 反例：`Popup` 做不到这一点。即使 `focusable = false`，Popup 自己的窗口区域
> 仍会消费触摸（系统窗口的 `FLAG_NOT_TOUCH_MODAL` 只保证**窗口外**穿透），
> 所以没走 Popup。

### 3. 只有两行 —— 超过就会在 2.5 秒内读不完

单测里有一条护栏 `标题必须短到一眼能读完`（标题 ≤ 12 字），
防止以后又把说明文塞回标题里。

### 其余细节

- **进出场动画**：`fadeIn() + slideInVertically(initialOffsetY = { -it })`，退场只 `fadeOut()`。
  退场时 `alert` 已经变成 `null`，用 `shown` 兜住最后一条内容，否则会闪成一个空框。
- **自动收起计时放在 `ScanScreen`**，不放在提示条内部：组件保持纯展示，
  谁决定它活多久由屏幕层掌握，组件被挪到别处也不会失控。
- **屏上有提示时允许被新的覆盖**（v1.7 是"不覆盖"）。因为提示条不拦截操作，
  "第二条被吞掉"比"旧信息被顶掉"更糟；频率由 `DuplicateMonitor` 的冷却兜住
  （单码 3 秒 / 全局 1.2 秒），不会一直闪。
- **配色**：`inverseSurface` 深底 + `inverseOnSurface` 浅字。浅色卡片叠在相机画面上
  会和取景内容糊在一起，深底在浅色/深色主题下都读得清。左侧一枚 7dp 红点
  替代"警告"二字——连续盘点时靠颜色识别比读字快。

## 五、还能再调的地方

- 时长：`DUPLICATE_HINT_MS`（`ScanScreen.kt`），觉得短就抬到 3000~3500ms。
- 位置：`padding(top = 72.dp)` 是 TopAppBar（64dp）下方 8dp；若机型的
  `TopAppBar` 高度不同，会略微偏移。
- 想更小：把 `fillMaxWidth()` 换成 `widthIn(max = 320.dp)` 可变成居中小卡，
  但会盖住取景框中心，暂不推荐。
