# v1.8.3 — 提示位置统一：删除撤销也挪到顶部

## 一句话

所有「一闪而过的提示」现在都从屏幕顶部同一个槽位出现：状态提示、复制结果、导出结果、
**删除后的「撤销」**、重复码轻提示。位置一样，样式也一样。

## 问题

v1.8.1 把重复码提醒从屏幕中央的模态对话框改成了顶部轻提示，但删除后的
「已删除 XXX ［撤销］」仍然是 Scaffold 自带的底部 Snackbar。于是同一种东西分居两处：

```
┌────────────────────────────┐
│  [重复码 · 未计入 ...]  ← 顶部  │
│                            │
│        （取景 / 列表）       │
│                            │
│  [已删除 xxx    撤销] ← 底部   │  ← 正好压在底栏按钮上
│ [复制全部][导出][清空]        │
└────────────────────────────┘
```

两个具体问题：

1. **底部 Snackbar 会盖住底栏 4 秒**。它挂在 Scaffold 的 `snackbarHost` 上，落点自动避开
   `bottomBar`，于是稳定地浮在「复制全部 / 导出 / 清空」这排按钮上面。盘点时删错一条
   想立刻重来，正好点不到，只能等它自己消失。
2. **同一种反馈有两种长相**。顶部是 12dp 圆角反转色小条，底部是 Material 默认的
   宽扁深色条，用户每次都要重新判断「这条是从哪儿冒出来的、要不要管它」。

## 改法

```
Box(fillMaxSize) {
    Scaffold(...)                     // 不再设 snackbarHost
    Column(TopCenter, statusBarsPadding, top = 72dp) {
        TopSnackbarHost(snackbarHostState)   // 原底部 Snackbar，改挂这里
        DuplicateHintOverlay(state.duplicateAlert)
    }
}
```

三条要点：

1. **落点统一**：`SnackbarHost` 从 Scaffold 里摘出来，与重复码提示放进同一个顶部 Column。
   两条提示的左边距（16dp）、圆角（12dp）、配色（`inverseSurface` 深底 + `inverseOnSurface`
   浅字）、阴影全部一致，看起来就是同一个组件。
2. **不互相遮挡**：竖排 + 8dp 间距。删除撤销（4 秒、带按钮）和重复码提示（2.5 秒、纯信息）
   有可能同时出现，同坐标叠放会互相盖住，竖排最多占两条高度。
3. **仍然不进布局**：这一整列是 `Box` 的叠层，出现/消失都不会把列表推得上下跳。

## 为什么撤销按钮放顶部不会难按

72dp 位于状态栏下沿、顶栏之下的缝隙里，单手拇指在 6 寸屏上属于可及区；
Snackbar 的「撤销」是水平排布的右侧按钮，不像底部那样需要考虑手势条遮挡。
如果真机上手发现够不到，可以改成「右侧竖排两个按钮」或把撤销时长放宽到 6 秒。

## 取舍记录

- **没做成「同一时刻只显示一条」**：那样删除撤销会把重复码提示挤掉，而重复码提示正是
  用户明确要求「不要影响继续扫描」的那条。宁可竖排占两条，也不静默丢信息。
- **没退回底部**：底部是三个高频按钮的位置，任何常驻几秒的浮层在那里都是净损失。

## 验收

- `240/240` 单测通过（本次为纯 UI 布局调整，无新增纯逻辑分支，故未加用例）。
- `versionCode 16 / 1.8.3`，权限仍只有 `CAMERA` + `VIBRATE`。
- 真机未验：顶部两条同时出现时的观感、撤销按钮的可点性需要上手确认。
