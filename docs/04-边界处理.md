# 四、边界处理

| 场景 | 处理方式 | 代码位置 / 关键行 |
|---|---|---|
| **暗光** | ① 顶栏旁常驻「闪光灯」开关，一键常亮；② 无闪光灯机型探测 `hasFlashUnit`，按钮点击时提示「当前镜头没有闪光灯」并复位状态而不是无效点亮；③ ML Kit 本身对低对比度有一定鲁棒性，暗光下的主要症状是「检测到有条码但解不出」，此时靠**潜在条码提示**告诉用户「有码但没解出来」。 | `CameraPreviewCard` 的 `LaunchedEffect(torchOn, camera) { cameraControl.enableTorch(torchOn) }`；`ScanViewModel.reportNoFlashUnitWhileTurningOn` |
| **模糊 / 残缺码** | 不靠「猜」补全。ML Kit 返回 `rawValue == null` 的潜在条码时，UI 弹黄条「疑似有码，再靠近 / 稳住一下」，1.2s 自动淡出。这类结果绝不写入列表（写进去就是一个没有内容或内容错误的记录，对账时是灾难）。同时明确提示靠近/对焦，而不是笼统的「请对准」。 | `BarcodeAnalyzer`：`potentialOnly = raw.isNullOrEmpty`；`ScanViewModel.onCodesDetected` 里 `decoded.isEmpty` 分支只 `potentialTick++` |
| **重复码** | **两级去重**：① **同帧去重**——一帧里出现多个相同码（如一张照片里有 5 个一样的 QR）只记第一条，恒定生效；② **跨帧去重**——1.5s 滑动窗口，且被拒绝的回调也刷新时间戳，因此持续对着同一个码不会刷屏。已仿真量化（`tools/verify_dedupe.py`）：固定对准同一个码 10 秒，本方案写入 **1 条**，而「只在计入时刷新」的固定窗口写法写入 **7 条**，完全不去重则 **189 条**（20fps）。<br>跨帧那级可被主屏的**去重开关**关闭：关闭后逐帧留痕（约 20 条/秒），此时**不写时间戳**，且切换开关时会 `dedupe.reset`，避免「关 → 开」后前 1.5 秒毫无响应；同帧去重不受开关影响。列表「清空」时同样 `dedupe.reset`，保证刚清空就能立刻重扫同一个码。<br>**已知取舍**：1500ms 窗口下，人工快速补扫同款（移开约 300ms）会被吞掉；把窗口调到 300ms 可解决，且仍不会刷屏（仿真已验证）。设置面板文案已显式提示这一点。 | `CodeAdmission.admit`；`DedupeTracker.shouldAccept`；`ScanViewModel.setDedupeEnabled` / `clearAll` |
| **快速移动** | ① `ImageAnalysis` 用 `STRATEGY_KEEP_ONLY_LATEST`，绝不积压帧（积压会导致画面「识别滞后几秒」，用户以为坏了）；② `imageProxy.close` 放在 `addOnCompleteListener`，形成天然闸门，杜绝多帧并发解析同一缓冲；③ 分析流锁 1280×720，单帧解析更快，快速扫一排货架时命中率更高；④ 反馈只在**真正计入**时触发，快速移动产生的大量重复帧不会引发连续震动噪音。 | `CameraPreviewCard` 的 `setBackpressureStrategy`；`BarcodeAnalyzer` 的 `addOnCompleteListener` |
| **权限拒绝** | 三态处理，任何一态都不白屏、都不崩：<br>① 未申请过 → 进页面自动请求一次；<br>② 拒绝但可再问 → 显示 `PermissionPanel`，含「授予相机权限」+「去系统设置」两个按钮，文案解释「画面全部本机离线处理，不上传不保存」；<br>③ 永久拒绝（`shouldShowRequestPermissionRationale == false`）→ 单按钮「去系统设置」，并说明系统不会再弹窗。<br>**降级兜底**：无论如何，顶栏「相册」按钮始终可点，没有相机权限也能靠图片完成识别。 | `ScanScreen.kt` 的 `permanentlyDenied` 计算与 `PermissionPanel`；`Context.openAppSettings` |
| **横竖屏切换** | ① Activity 不锁方向（`fullSensor`），`ViewModel` 在配置变更时存活 → 结果列表与去重器状态都不丢；② 预览方向由 CameraX 计算 `imageProxy.imageInfo.rotationDegrees` 后交给 `InputImage.fromMediaImage`，无需任何矩阵变换代码；③ `DisposableEffect(lifecycleOwner)` 在重建时重新绑定，`onDispose` 里 `unbindAll` + 关闭线程池 + `scanner.close`，不泄漏；④ `disposed` 标志防止 `ProcessCameraProvider` 异步回调打在已销毁的 `PreviewView` 上；⑤ 布局用 `weight` 而非固定 dp，横屏时预览与列表按比例分配。 | `MainActivity`（不写 `configChanges`）；`CameraPreviewCard` 的 `DisposableEffect` / `onDispose` |
| **后台返回** | ① 相机随 `Lifecycle` 自动关闭（`bindToLifecycle`），后台不占摄像头、不耗电；② 返回前台自动重绑，无需手动 `onResume` 处理；③ 从系统设置返回时 `ON_RESUME` 重新校验相机权限；④ 一次性提示不会重放：Snackbar 走 `SharedFlow(replay = 0)`，不会在回到前台时又弹一遍「已复制 12 条」；⑤ 切后台拍照导致进程被系统回收时，列表会丢失（需求明确不落库）。 | `ScanScreen` 的 `LifecycleEventObserver`；`ScanViewModel._events` 的 `replay = 0` |
| 相机被占用 / 无后置镜头 | `bindToLifecycle` 包 `runCatching`，失败时通过 `onError` 上报为可读 Snackbar（例如「识别异常，已自动恢复：…」），**不崩溃**；同时权限面板与相册入口仍可用。 | `CameraPreviewCard` 的 `runCatching { ... }.onFailure { currentOnError(it) }`；`ScanViewModel.onAnalyzerError` |
| **单帧解析失败** | `addOnFailureListener` 只上报、不中断，`addOnCompleteListener` 仍会释放 `ImageProxy`，所以**下一帧照常来**。镜头切换瞬间的空 `Image` 也直接 `close` 放行。 | `BarcodeAnalyzer.analyze` |
| 提示音/马达不可用 | `ToneGenerator` 构造在部分机型/模拟器会抛 `RuntimeException`；`Vibrator` 在少数设备上 `hasVibrator` 为 false。全部包 `runCatching` 静默降级——反馈失效不能影响识别。提示音额外做 60ms 节流，避免「哒哒哒」连成噪音。 | `FeedbackPlayer.beepOnce` / `vibrateOnce` |
| **列表过长** | `LazyColumn` 只渲染可见项；`key = seq` 保证插入/删除不整表重组；去重器超过 512 条目自动清理过期键。 | `ResultListPanel`；`DedupeTracker.maybePruneLocked` |
