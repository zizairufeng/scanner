## 一、方法：我查了什么

对比了国内外同类工具的功能设置（条码云、超级盘点机、诺动条码、条码扫描宝、
DataScan、Barcode Scanner to Sheet、UPC Scanner、Stock Count），
并核对了 ML Kit 官方文档的当前能力。

结论是：**业界盘点类 App 的功能收敛度很高**，重复出现的功能就那几样。
我按「是否符合本 App 的既有定位」筛了一遍，剩下 11 条。

## 二、必须守住的三条底线（筛选依据）

本 App 的需求里有三条硬约束，任何新增功能都不能破：

| 约束 | 含义 | 会直接否决的功能 |
|---|---|---|
| **仅 CAMERA 权限** | 不申请存储 / 位置 / 通讯录 | GPS 定位、相册读写（现相册用系统选择器，合规） |
| **零网络依赖** | 飞行模式下功能完整 | 云同步、账号体系、SMTP / FTP 上传 |
| **端侧离线识别** | 模型打进 APK | 任何需要联网的服务端识别 |

下面所有提案都在这三条之内。

## 三、现状缺口盘点

先说清楚现在**缺什么**，避免提案里混进已有功能。已实现的不在此列：
7 码制、连续扫描、去重开关、时间窗、复制三格式、震动/提示音、闪光灯、
双击缩放、相册识别、单删/清空。

| 缺口 | 现在的行为 | 后果 |
|---|---|---|
| 结果只能进剪贴板 | 点「复制全部」后需自己找地方粘贴 | 几百条数据粘微信很难受；换设备只能重扫 |
| 退出即丢 | 不落盘 | 误触返回键 / 系统回收进程 → 数据**全没**，且不可恢复 |
| 无数量概念 | 重复扫 = 或拒绝、或多条 | 盘点最核心的「这个码有几个」要人工数 |
| 扫不出只能放弃 | 只有相机和相册两条路 | 条码磨损、反光、褶皱时无补救手段 |
| 长列表难定位 | 只能滚 | 200 条里找某个码要滚很久 |
| 变焦靠手 | 只有双击缩放 | 远处小码要反复凑近，是识别失败的主因 |

## 四、候选功能

### A 档 · 我强烈推荐（4 条）

#### F1 · 自动变焦（ML Kit auto-zoom）

**痛点**：远距离小码解不出来，只能靠人把手机凑近或手动双击缩放。这是识别失败的第一主因。

**做法**：ML Kit 从 **17.2.0** 起提供 `setZoomSuggestionOptions()`——当画面里的码都太远、
无法解码时，库会回调一个建议的 zoom ratio，App 拿它调 `cameraControl.setZoomRatio()` 即可。
我们用的正是 **17.3.0**，依赖已满足，无需升版、无需新权限。

**代价**：代码约 20 行。**APK 体积 0 增量**（能力已打在现有库里）。

**风险**：低。唯一要注意——建议值可能超过硬件上限，必须 `setMaxSupportedZoomRatio()`
把相机实际最大值传进去，否则会拿到不支持的倍数。另外它只在「一帧内什么都没解出来」时
触发，不会和手动缩放打架（手动缩放优先）。

**验收**：对准 2 米外的 EAN-13，观察是否自动放大并解出；手动双击缩放时应不被自动变焦抢回。

---

#### F2 · 计数聚合（×N）

**痛点**：盘点的核心问题是「这个码有几个」，现在完全没有数量概念。
扫到第 2 个同样的码时，要么被去重拒绝、要么多占一行，都得人工数。

**做法**：把现在的「去重开关（布尔）」升级为**三态模式**：

| 模式 | 重复扫到同一个码时 | 适用 |
|---|---|---|
| **严格去重**（当前"开"） | 不计入 | 资产盘点、序列号采集 |
| **计数聚合** ← 新增 | 该行数量 **+1**，仍只占一行 | **箱数盘点、同款商品清点** |
| **允许重复**（当前"关"） | 新增一行 | 需要逐次留痕的特殊口径 |

列表行尾显示 `×3`；导出时多一列「数量」。
注意：**时间窗防刷屏在三种模式下都继续生效**，不会出现一秒记十几条。

**代价**：改动集中在 `CodeAdmission` / `ScanItem` / `ResultListPanel` / `CopyFormatter`。
`ScanItem` 加 `qty` 字段。**体积 0 增量**。

**风险**：中——这是**语义改动**，会动到现有去重开关的 UI。但它正好把现在
「开 / 关」两个布尔状态整理成一个清晰的三选一，长期更好维护。
单测要跟着扩（`CodeAdmissionTest` 现在 12 个用例）。

---

#### F3 · 导出为文件 + 系统分享

**痛点**：现在结果只能进剪贴板。几百条数据粘到微信/QQ 经常掉格式、超长度，
也没法直接存成文件归档或发给别人。

**做法**：在「复制全部」旁边加「导出」——把结果写成 `.csv` / `.txt` 文件，
通过 `FileProvider` + `ACTION_SEND` 交给系统分享面板（微信、QQ、邮件、网盘、
蓝牙全都能收）。走的是系统分享，**不加任何权限、不联网**。

**代价**：代码约 60 行（FileProvider 配置 + provider_paths + 分享 Intent）。
体积约 +2KB。

**风险**：低。FileProvider 是 androidx.core 自带的，无新依赖。
需要注意 `provider_paths.xml` 的路径声明，写错了会抛
`IllegalArgumentException: Failed to find configured root`——这是该功能的经典坑，
我会写单测并真机验证分享面板能拉起。

---

#### F4 · 会话防丢（本地持久化）

**痛点**：**这是最该补的一条。** 现在数据纯在内存里，误触返回键、切到别的应用久了
被系统回收、或者手滑清了后台 → 全部扫码结果**瞬间归零且不可恢复**。
盘到一半丢数据的代价，比任何功能缺失都大。

**做法**：每次列表变动后异步写入 App 私有目录（`filesDir/session.json`，
用 Android 自带的 `org.json`，**不引三方库**）。冷启动时若发现上次会话未收尾，
弹一条「恢复上次未完成的 N 条？」，用户选恢复或丢弃。

**代价**：代码约 80 行。体积 +5KB 左右。

**风险**：低-中。两点要说清：
1. 写盘时机——不能每条都同步写（IO 阻塞主线程），用「变动后 500ms 合并写一次」；
2. 「不落盘」原本是设计选择（隐私好），改成持久化后要给出**明确的清空入口**，
   并保证导出/清空后文件也删掉，避免数据残留。

如果你在意隐私，可以做成**默认关闭、设置里手动开**——你定。

### B 档 · 实用增强（4 条）

#### F5 · 手动输入条码
条码磨损、反光、褶皱时相机解不出，手输补一条。输入框在列表顶部，
计入后与扫码记录**同等对待**（同序号、同导出）。业界同类 App 普遍都有。
代价：约 30 行，+3KB。

#### F6 · 条码规则过滤
设「前缀 / 长度 / 正则」白名单，只有匹配的码才计入。
例：只收以 `69` 开头、长度 13 的 EAN；货架上混着别的码时不会被误扫进去。
代价：约 40 行（含一个可单测的 `CodeFilter` 纯函数），+2KB。

#### F7 · 列表搜索
顶部搜索框，输入即高亮/过滤。200+ 条时定位某个码从「滚很久」变成「输 4 位」。
代价：约 25 行，+2KB。

#### F8 · 顶部统计条
一行显示：**总条数 / 唯一码数 / 数量合计**。盘点收尾时对总数很有用，
不用滚到底去数。代价：约 15 行，+1KB。

---

### C 档 · 锦上添花（3 条）

#### F9 · 撤销删除
误删一条时能撤销。删完弹 Snackbar「已删除 · 撤销」，5 秒内可恢复。
比现在的「删了就没」安全。代价：约 25 行，+2KB。

#### F10 · 长按暂停扫描
按住预览区即暂停计入，松手恢复。用于「镜头要路过一堆干扰码、
但不想把它们记进去」的场景（DataScan 有同名功能）。代价：约 20 行，+1KB。

#### F11 · 导出 XLSX（真 Excel 文件）
CSV 在 Excel 里打开常遇编码/分隔符问题。直接生成 `.xlsx` 更省事。
xlsx 本质是 zip + XML，可以用 `java.util.zip` 手写，**零第三方依赖**。
代价：约 150 行（比 CSV 麻烦不少），+8KB。

## 五、我明确排除的功能（附理由）

搜出来但**不建议做**的，免得你误以为我漏了：

| 功能 | 为什么排除 |
|---|---|
| 云同步 / 账号 / 团队协作 | 与「零网络依赖」直接冲突，且要引入服务器成本 |
| GPS 定位打标 | 需要 `ACCESS_FINE_LOCATION`，破「仅 CAMERA」 |
| 拍照存证 | 需存储权限，且偏离盘点主线（属审计场景） |
| 蓝牙扫码枪（HID） | 需外接硬件，与本 App「手机替代 PDA」的定位相反 |
| 条码生成 / 打印 | 是「制码」不是「扫码」，另一类需求 |
| OCR 文字识别 | 要再打一个 ML Kit 模型，体积 +数 MB，与刚做的瘦身相抵 |
| FTP / SMTP 自动上传 | 要联网 + 配凭据，破离线定位 |

## 六、组合建议

如果让我替你选，我会这样分优先级（你可以全盘推翻）：

| 套餐 | 内容 | 说明 |
|---|---|---|
| **最小可行** | F1 + F4 | 一个解决「扫不到」，一个解决「数据丢」。改动小、风险低、收益最高 |
| **推荐** | F1 + F2 + F3 + F4 | A 档全上。这四条覆盖了识别率、数量、交付、安全四个维度 |
| **全量** | A + B + C 共 11 条 | 功能最全，但一次改 11 处，回归验证量大，建议分批上 |

体积方面可以放心：**11 条全做，预计增量也不到 30KB**，
相对当前 10.87 MB 的包体基本无感知——不会出现「加了功能又把包撑大」的情况。
