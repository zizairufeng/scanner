# 二、架构设计

## 一句话数据流

**相机帧 → ImageAnalysis（单线程 Executor）→ ML Kit 解析成纯数据 → 帧级准入（同帧去重 + 可开关的跨帧时间窗去重）→ ViewModel 的 StateFlow → Compose 列表与剪贴板。**

## 模块划分

| 包 | 类 | 职责 |
|---|---|---|
| `com.example.scanstock` | `MainActivity` | 唯一 Activity，edge-to-edge 宿主，不做业务 |
| `.domain` | `ScanItem` / `DetectedCode` / `CopyFormat` | 纯 Kotlin 数据模型，**零 ML Kit 依赖**，换识别库不用改这些 |
| `.domain` | `DedupeTracker` | 跨帧去重的时间窗，纯逻辑、可单测（时间可注入） |
| `.domain` | `CodeAdmission` | 帧级准入判定：同帧去重（无条件）+ 跨帧去重（受 `dedupeEnabled` 开关控制）。抽到 domain 层才能被纯 JVM 单测覆盖 |
| `.domain` | `CopyFormatter` | 三种复制格式的纯函数变换，CSV 转义在此 |
| `.camera` | `BarcodeFormats` | 码制白名单 + 扫描器工厂 + 常量→中文名映射（全工程唯一依赖 ML Kit 的入口之一） |
| `.camera` | `BarcodeAnalyzer` | `ImageAnalysis.Analyzer` 实现；负责 `imageProxy.close()` 背压闸门 |
| `.camera` | `ImageDecoder` | 相册图片 → `InputImage.fromFilePath` → 扫描，运行在 `Dispatchers.IO` |
| `.util` | `TaskAwait` | Play Services `Task<T>` → 挂起函数，避免多引一个依赖 |
| `.feedback` | `FeedbackPlayer` | 震动 30ms + `TONE_PROP_BEEP`，含 API 24 兼容分支与静默降级 |
| `.ui` | `ScanUiState` / `UiEvent` | 唯一状态源 + 一次性事件（剪贴板请求走事件，不走 StateFlow） |
| `.ui` | `ScanViewModel` | 状态容器：唯一写入 `StateFlow` 的地方；持有去重器与序号发生器 |
| `.ui` | `ScanScreen` | 权限流、剪贴板、Photo Picker、Scaffold 装配 |
| `.ui.components` | `CameraPreviewCard` | CameraX 绑定、闪光灯、双击缩放、取景框与提示浮层 |
| `.ui.components` | `ResultListPanel` | LazyColumn 结果列表，`key = seq` |
| `.ui.components` | `SettingsSheet` | ModalBottomSheet 设置面板 |
| `.ui.components` | `PermissionPanel` | 权限降级页（含永久拒绝分支） |
| `.ui.theme` | `ScanStockTheme` | 固定配色（关闭 Material You 动态色，保证语义色对比度稳定） |

## 三条不可违反的线程/职责规则

1. **分析器回调里绝不碰 UI**：`BarcodeAnalyzer` 只做「图像 → 不可变数据」的转换，产出 `List<DetectedCode>`；一切状态变更都在 `ScanViewModel` 里通过 `MutableStateFlow.update {}` 完成。
2. **剪贴板 / 震动等系统服务不由 ViewModel 直接驱动 UI**：震动属于设备反馈，ViewModel 直接调用可接受；剪贴板属于 UI 语义，通过 `UiEvent.CopyToClipboard` 下发给 Compose 层执行。
3. **一次性提示不进 StateFlow**：Snackbar 用 `SharedFlow`。若放进 `StateFlow`，旋转屏幕后状态恢复会重放一遍「已复制 12 条」。
