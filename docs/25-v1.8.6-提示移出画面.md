# v1.8.6 — 提示全部移出取景画面

## 一句话

v1.8.4 把 8 处浮层收敛成 3 个落点，但这 3 个落点**全都在相机画面上**；
这一版把画面清空——只剩取景框，所有提示搬进画面正下方一条固定 52dp 的状态栏。

## 用户的原话

> 不要在镜头显示的地方放浮窗呀，都看不到是否清楚了。

这句话点到了根上。扫码的核心动作是「对准」，而判断有没有对准**只能看画面**。
半透明胶囊叠在取景框里，恰好盖住用户唯一需要判断的那块像素。
提示再统一、再好看，只要它压在画面上，就是在妨碍主任务。

v1.8.4 的复盘错在这里：当时把「乱」理解成了「位置太多、颜色太杂」，
于是做的是**归并**（8 处 → 3 个落点、6 色 → 3 色）。归并是必要的，但不充分——
归并的结果仍然全在画面内。真正该问的是「这块信息有必要画在画面上吗」。

## 改动前后

```
改前（v1.8.4）                       改后（v1.8.6）
┌────────────────────┐              ┌────────────────────┐
│ ● 重复码 · 未计入   │  ← 72dp      │                    │
│                    │              │                    │
│   ┌──┐      识别4fps│              │    ╭────────╮      │  ← 只有取景框
│   │  │             │              │    │  ◎     │      │     （细线 + 准星）
│   ╰──╯             │              │    ╰────────╯      │
│   疑似有码 · 靠近   │  ← 底 14dp   │                    │
│             1.0x   │  ← 右下       ├────────────────────┤
│  复制全部 / 导出/清空│              │ ● 对准条码 · 自动识别 │  ← 52dp 状态栏
└────────────────────┘              └────────────────────┘
```

- **画面里只剩取景框本体**：四个角标 + 中心准星。那是瞄准器，不是提示。
- **其余全部进状态栏**：重复码、撤销、失焦、疑似有码、识别回执、位置引导、
  识别吞吐、缩放倍率（并入下方操作行的文案）。

## 状态栏规格

| 项 | 值 | 理由 |
|---|---|---|
| 高度 | 52dp **固定** | 内容切换时高度不变，画面不会跟着跳 |
| 底色 | `#121719` 恒定 | 长在相机卡片上，跟着明暗主题变会很怪 |
| 分隔线 | 1dp `#1FFFFFFF` | 与画面分层，但不抢眼 |
| 排版 | 圆点 + 两行文字 + 可选按钮 | 第一行结论/该做什么，第二行码值 |
| 圆点 | 7dp，只有它带语义色 | 文字统一白色，避免「每条一个底色」回潮 |

原本只是单行，实现时发现**码值没地方放**：重复码提示如果把「第 3 行 · 第 2 次」
和码值都塞进一行，14sp 中文在 360dp 屏上必被截断。改成两行结构，
第一行放结论，第二行放等宽码值，52dp 刚好放得下（20 + 16 + 呼吸）。

## 优先级（唯一的信息调度规则）

所有提示挤在同一条里，「谁顶替谁」就成了唯一要紧的事。规则写在
`ScanScreen.statusOf()` 这一个纯函数里，顺序即优先级：

| 顺序 | 内容 | 为什么排这儿 |
|---|---|---|
| 1 | 撤销（带按钮） | 唯一「错过就找不回」的一条，4 秒窗口 |
| 2 | 重复码 | 「这次算没算」只有它会说，列表里看不到 |
| 3 | 太近失焦 | 用户正在做错一件事，比任何回执都急 |
| 4 | 疑似有码 | 方向性引导 |
| 5 | 识别回执 | 列表第一行就是它，只是确认一下 |
| 6 | 位置引导 | 新手常识，谁都能打断 |
| 7 | 识别吞吐 | 诊断信息 |
| 8 | 常驻引导 | 什么都没有时的底噪，顺便占住高度 |

**底噪是有用的**：状态栏高度必须恒定，空着不如写一句「对准条码 · 自动识别」——
既填满了空间，又对新手是句真话。

## 连带的结构调整

1. `CameraPreviewCard` 从 `Box` 改成 `Column { 画面(weight=1f) ; statusBar() }`，
   圆角裁在整体上，视觉上是「取景窗 + 相机状态栏」一整块。
2. `pointerInput`（单击对焦/双击缩放）只挂在**画面区**那层 Box 上，
   状态栏在它下方，按钮点击不会被相机手势吃掉。
3. 预览卡片权重 0.42 → **0.46**：卡片内部固定分走 52dp 给状态栏，
   净给画面的高度和以前基本持平，但画面里从此干净。
4. Snackbar 不再用 `SnackbarHost` 浮层，改成读 `currentSnackbarData` 渲染进状态栏。
   撤销按钮仍然可点，超时仍由 `showSnackbar` 的 duration 管。
5. 删掉 `HintCard` / `DuplicateHintOverlay` / `HitHintOverlay` / `TopSnackbarHost` /
   旧 `ScanHint.kt`；提示只留 `ScanStatusBar` 一个组件。
6. `HintSuccess` 从 `1FA96F` 提到 `3DD68C`：那版是画在浅色胶囊上的，
   这版画在近黑状态栏上，同一个绿在黑底上会显脏。

## 验收

- 253/253 单测通过（244 + 9 条新增）：
  - `ScanHintSpecTest` 5 条：时长两档 / 语义三种 / 状态栏高度能装下两行和撤销按钮 /
    圆点不大于文字 / 位置引导不常驻；
  - `StatusPriorityTest` 8 条：撤销压过一切 / 重复码压过失焦和回执 /
    重复码三段信息齐全 / 失焦压过回执 / 回执压过位置引导 / 性能最低 /
    空状态有内容 / 无动作不渲染按钮。
- versionCode 19 / 1.8.6。
