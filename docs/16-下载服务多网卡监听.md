# 下载服务改为多网卡监听

日期：2026-10-08　｜　影响范围：`tools/serve-apk.js`（不进 APK，无需重新出包）

## 起因

一句反馈：「100.85.243.81 这个也可以下载」。

这句话点破了一处判断失误：上一版把「服务绑到 Tailscale 地址」定性为**故障**
并"修正"掉了——因为它导致手机连同一个 Wi-Fi 时打不开。但这其实是个二选一被我当成了单选题：

| 地址 | 谁能访问 | 什么时候有用 |
|---|---|---|
| `192.168.2.150` | 同一 Wi-Fi 的手机 | 在家 / 办公室，最快 |
| `100.85.243.81`（Tailscale） | 装了 Tailscale 并加入同一 tailnet 的设备 | **在外面也能下**，不受 Wi-Fi、AP 隔离影响 |

两条路各有各的用处，**没有理由只留一条**。

## 根因：一个 `http.Server` 一次只能绑一个 host

Node 的 `server.listen(port, host)` 里的 `host` 是单值。所以早先的实现只能：

```js
const lans = lanAddresses();          // 枚举出所有外部地址（已按"适合手机访问"排序）
const host = args.host || lans[0];    // 挑第一个绑
```

`lans[0]` 挑哪个取决于 `os.networkInterfaces` 的返回顺序，而**这个顺序不保证**。
于是两种失败都实测遇到过：

1. 挑中 Tailscale → 手机同 Wi-Fi **打不开**，但服务在跑、日志正常、端口在监听（最难查的那类故障）；
2. 挑中以太网 → 手机在**外面**下不了，哪怕它其实已经装了 Tailscale。

上一版用「地址档位排序」把 (1) 压住了（`192.168.*` > `10.*` > 私有段 > 其他 > CGNAT 最后），
但 (2) 依然存在——排序只能改善"挑得对"，解决不了"只能挑一个"。

## 改法

为每个外部地址各起一个 listener：同一端口、同一份内容、共用一个请求处理函数。

```js
for (const host of targets) {
  const srv = http.createServer(handleRequest);   // handler 提成具名函数，多 server 共用
  srv.on('error',  (err) => { settled.push({ host, ok: false, err }); maybeReport(); });
  srv.listen(args.port, host, () => { settled.push({ host, ok: true }); maybeReport(); });
  servers.push(srv);
}
```

三个关键设计：

1. 单个地址绑不上不拖垮整条服务。Tailscale 可能刚退出、网卡可能还没拿到 DHCP 地址、
   某个 IP 也可能被别的进程单独占了——只要还有一条通路活着就有用。
   只有**全部**失败才退出（`exit 1`）。
2. **`handleRequest` 必须是具名函数**，不能是内联箭头函数——多 server 要共用同一套逻辑，
   内联就得复制一份或者闭包套娃。
3. 报告等所有地址都 settled 再打一次，否则日志会分成两段、看着像起了两次。

### 日志按通路分组

`192.168.2.150` 和 `100.85.243.81` 混在一行里列出来，用户还得自己猜哪个对应哪种情况。
所以按通路分组、各带一句人话说明：

```
  监听 2 个地址（同一份内容、同一个端口），任一条通即可：

  同一 Wi-Fi 的手机（手机连的是家里/办公室的 Wi-Fi）
    http://192.168.2.150:8080/

  Tailscale 设备（装了 Tailscale 并加入同一 tailnet，任意网络都能下）
    http://100.85.243.81:8080/
```

### 参数变化

| 之前 | 现在 |
|---|---|
| `--host` 只接受一个地址 | `--host` 可重复、可逗号分隔（`--host a --host b` / `--host a,b`） |
| 默认 `lans[0]`（挑一个） | 默认 `lans`（**全部外部地址**） |
| `--host 0.0.0.0` 是"绑所有网卡"的唯一途径 | 仍然支持，但默认行为已经是"所有外部地址"，只是不含回环 |

## 验证（实测，非推断）

```
TCP    100.85.243.81:8080     0.0.0.0:0              LISTENING       16040
TCP    192.168.2.150:8080     0.0.0.0:0              LISTENING       16040
```

| 入口 | 结果 |
|---|---|
| `http://192.168.2.150:8080/` | 200，含 1.5.0 链接 |
| `http://192.168.2.150:8080/ScanStock-1.5.0-release.apk` | HEAD 200，`Content-Length` 11,593,464 |
| `http://100.85.243.81:8080/` | **200**（同一进程，PID 16040） |

> 注意：从本机用 Python `urllib` 测 `100.85.243.81` 会失败——那是**沙箱代理**把这个
> CGNAT 段当外网拦了，不是服务的问题。改用 Node 的 `http.request` 直连即可（实测 200）。

## 运维注意

- **`_serve_ctl.py` 的告警判据变了**。原来是「绑定地址 ≠ 局域网地址 → 告警」，
  多地址之后会误报。现在改成「有没有至少一个局域网地址在监听」——
  只要有，手机同 Wi-Fi 就能下；Tailscale 那条是额外赠送的，没有也不算故障。
- 状态输出会把每个监听地址标上通路：
  ```
    [运行中] 2 个地址在监听   PID 16040
      [同 Wi-Fi]    http://192.168.2.150:8080/
      [Tailscale]  http://100.85.243.81:8080/
  ```
- **仍然不绑回环**。探测存活继续用 `netstat` 判据，别用 `http://127.0.0.1:8080` 去试。
- 本次改动不影响 APK。`tools/` 目录不参与打包，`dist/` 里的 1.5.0 包原样可用，
  不需要重新构建、也不需要用户重装。
